# URALSTORE

Статический сайт: https://igoruralst66.github.io/uralstore-norms/

## Ремонты v1

`repairs.js` / `repairs-model.mjs` / `repairs.css` — отдельный раздел, не меняющий данные нормативов. Для локального просмотра нужен HTTP-сервер, например `python3 -m http.server 8765`; открытие `index.html` через `file://` не поддерживает модули.

Реальные заказы доступны только вошедшим сотрудникам из `public.repair_members`. Демо использует только вымышленные данные в памяти вкладки. Авторизация ремонтов хранится в sessionStorage; клиентские данные не кешируются и не включаются в экспорт нормативов.

`supabase-repairs.sql` — одноразовая транзакционная миграция. Применена 01.10.2026 к текущему проекту. Не запускать повторно. RLS включён на всех трёх таблицах; анонимный доступ и прямые изменения закрыты. Запись заказа и неизменяемого журнала идёт одной транзакцией через `save_repair`. Устаревшая версия заказа отклоняется, чтобы не потерять изменения другого сотрудника.

Для нового сотрудника администратор создаёт/приглашает пользователя в Supabase Auth, затем добавляет его UUID и имя в `repair_members`. Самостоятельная регистрация не выдаёт доступ. Деактивация — `active=false`. Пароли и серверные ключи не включать в файлы сайта. Разрешённый URL для входа по письму: `https://igoruralst66.github.io/uralstore-norms/`.

Стоимость пустая = неизвестна, ноль = бесплатно. Оплата учитывает частичный взнос. Кнопка «Оплачено клиентом» заполняет полученную сумму до полной стоимости; сохранение выполняется кнопкой «Сохранить». Сервис оплачивается отдельно. Отметка FS — ручная отметка сверки, она не изменяет Google-таблицу. Закрытие доступно после статуса «Выдан» и завершения обоих расчётов. Повтор ссылается на более ранний заказ. История показывает последние 100 событий заказа; все события остаются в базе.

Проверка расчётов: `node --test tests/repairs.test.mjs`. База проверена транзакционными тестами с откатом: отказ для не-сотрудника, создание, аудит, конфликт версии, переплата, закрытие с долгом и после расчётов. Реальных заказов при проверке не создавалось. UI: частичная/полная оплата, запись события, выдача, запрет закрытия с долгом, архив после расчётов.

Из Google-таблицы реальные клиентские записи ещё не импортировались. Изменение сайта не требует замены или очистки таблицы `norms`.
