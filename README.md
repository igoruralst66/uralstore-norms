# URALSTORE

«Офис URALSTORE» — мини-приложение для внутренних процессов магазина: нормативы, выкуп, контроль товаров, ремонты, смены и мотивация сотрудников.

Рабочий сайт: https://igoruralst66.github.io/uralstore-norms/

> Локальная версия может быть новее опубликованного сайта. Перед продолжением работы сравните локальную ветку `main` с `origin/main`.

## Карта проекта

- `index.html` — оболочка приложения, общий вход, навигация, нормативы и обзор.
- `repairs.js` — экран ремонтов и работа с общей базой.
- `repairs-model.mjs` — расчёты и проверки данных ремонтов.
- `repairs.css` — оформление раздела ремонтов.
- `staff.js` — сотрудники, общие смены, оклады, бонусы и штрафы.
- `buyback.js` и `buyback.css` — общий справочник цен выкупа, категории и журнал изменений.
- `turnover.js` и `turnover.css` — интерфейс контроля отдельных товарных позиций.
- `turnover-sync.mjs` — синхронизация контроля товаров, резервирование исходной копии и перенос без перезаписи общих данных.
- `supabase-turnover-sync.sql` — новый общий контроль товаров и защищённая история; требуется однократный ручной запуск до публикации подключения.
- `office-export.js` — единая выгрузка основных разделов в Excel для администратора.
- `office-backup.js` — полная JSON-копия рабочих данных и восстановление поддерживаемых разделов.
- `PROJECT_CONTEXT.md` — бизнес-логика проекта простым языком и список следующих шагов.
- `supabase-repairs.sql` — первая миграция базы ремонтов. Повторно не запускать.
- `supabase-repairs-drafts.sql` — поддержка черновиков и защищённой истории ремонтов. Повторно не запускать.
- `supabase-add-notes.sql` — добавление заметок к нормативам.
- `supabase-staff-sync.sql` — общая база смен и мотивации с синхронизацией между устройствами.
- `tests/repairs.test.mjs` — автоматические проверки расчётов ремонтов.

Логика смен и мотивации находится только в `staff.js`; старая дублирующая реализация из `index.html` удалена. Следующий технический этап — вынести их оформление в отдельный файл стилей.

## Как открыть локально

Для полного просмотра, включая ремонты, нужен локальный HTTP-сервер:

```text
python3 -m http.server 8765
```

После этого открыть `http://127.0.0.1:8765/`.

Обычное открытие `index.html` через `file://` подходит для части интерфейса, но браузер может заблокировать модуль раздела ремонтов.

## Где хранятся данные

- Нормативы и ремонты используют Supabase.
- Смены и мотивация используют общую базу Supabase; `localStorage` остаётся локальной резервной копией.
- Полная JSON-копия включает нормативы, выкуп, сотрудников, смены, мотивацию, ремонты, историю ремонтов и локальный контроль товаров.

Кнопка «Скачать Excel» формирует один файл с отдельными листами по доступным разделам. Это рабочий отчёт для просмотра. Для сохранения состояния проекта администратор использует кнопку «Скачать копию», которая создаёт JSON-файл.

Кнопка «Восстановить копию» заменяет нормативы, выкуп, сотрудников, смены, мотивацию и локальный контроль товаров данными из JSON. Ремонты и их защищённая история входят в скачанную копию как архив, но автоматически обратно не записываются, чтобы массовое восстановление не повредило журнал действий.

У каждого сотрудника есть редактируемый дневной оклад. Статусы `РС`, `ОС` и `ЗО` создают запланированную рабочую смену, а оклад попадает в мотивацию только после отдельного закрытия смены. Итог мотивации считается как оклад за закрытые смены плюс бонусы минус штрафы.

## Безопасность

Не записывать в публичные файлы сайта:

- коды доступа;
- пароли;
- секретные серверные ключи;
- персональные данные клиентов в документацию или тестовые примеры.

Код доступа к ремонтам проверяется внутри Supabase и отсутствует в публичных файлах сайта. После пяти неправильных попыток текущая сессия временно блокируется.

Локальная версия v1.1 использует общий вход с двумя серверными ролями:

- сотрудник видит ремонты, смены и мотивацию;
- администратор дополнительно видит обзор и нормативы.

Коды хранятся в Supabase только в виде хешей. После пяти неправильных попыток устройство блокируется на 15 минут. Обычная перезагрузка сохраняет вход, а кнопка «Выйти» завершает локальную сессию. Миграция доступа находится в `supabase-app-access.sql`; сами коды в файл не включены.

Ролевой вход, общие смены и мотивация опубликованы на GitHub Pages. Синхронизация между устройствами проверена 02.10.2026.

## Ремонты

Карточку ремонта можно сохранить как незаполненный черновик. Стоимость пустая означает «ещё неизвестна», а ноль — бесплатную работу. Оплата клиента и расчёт с сервисом учитываются отдельно.

Раздел открывается сразу после общего входа и не требует отдельного обязательного ввода имени. Имя редактора необязательно: его можно задать кнопкой в шапке или в самой карточке, а без него запись сохраняется от имени «Сотрудник». Имя общее с разделом выкупа.

Закрытие ремонта доступно после статуса «Выдан» и завершения обоих расчётов. Каждое сохранение создаёт запись в истории действий. Повторный ремонт может ссылаться на более ранний заказ.

На телефоне смены и мотивация показываются отдельными карточками выбранного сотрудника вместо широкой таблицы; на компьютере остаётся табличный вид.

Проверка расчётов:

```text
node --test tests/repairs.test.mjs
```

Из Google-таблицы реальные клиентские записи в приложение не импортировались.

## Как продолжить в новом чате

### Синхронизация контроля товаров — выпуск 08.10.2026

SQL `supabase-turnover-sync.sql` применён 08.10.2026 в проекте `cwzobgsgsfbcaryspunh`. Созданы отдельные таблицы `turnover_shared_state` и `turnover_events`; существующие разделы не менялись. Первичную миграцию повторно запускать не нужно. После выполнения исправлены неоднозначное имя переменной проверки и код конфликта версий. Для конфликта используется `PT409`, а не `40001`: последний мог вызывать бесконечные повторы PostgREST (см. https://supabase.com/docs/guides/troubleshooting/high-cpu-and-infinite-transaction-retries-when-using-custom-error-codes-in-rpc-functions-77326b).

Исходный ключ `uralstore_turnover_prototype_v01` остаётся нетронутым. Перед переносом точная исходная строка сохраняется в `uralstore_turnover_before_sync_v01`. Общий кэш хранится отдельно. Сервер добавляет только отсутствующие ID, сохраняет существующие общие записи и не возвращает удалённые карточки. Ключ переноса и серверная квитанция защищают от повторного импорта; конфликтные записи остаются в исходной копии. Копию с localhost или file:// нужно скачать на исходной странице и перенести через кнопку раздела на рабочем сайте: браузеры не делят данные разных адресов.

Сохранения проверяют версию на сервере. При конфликте или сбое сети черновик остаётся в `uralstore_turnover_unsaved_v01`, а общая версия не перезаписывается автоматически. Кнопка «Скачать копию этого устройства» сохраняет и исходную копию, и такой черновик. Экспорт Excel/JSON в новой версии читает общий контроль; импорт JSON дополняет контроль без замены существующих записей.

Две независимые реальные сессии проверены: создание сотрудником, редактирование, реализация и возврат, удаление администратором, запрет удаления сотрудником, конфликт версий, повторный перенос и защита от возврата удалённых записей. Данные выкупа до и после теста совпали. Вымышленные тестовые карточки и категории удалены; записи о проверках остаются в защищённом журнале. Клиентские тесты дополнительно покрывают точную исходную копию, сбой сети, старые ответы и выход из сессии.
